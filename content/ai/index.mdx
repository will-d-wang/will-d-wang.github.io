# AI for Engineering

Use AI to help explore an unfamiliar system, propose a small change, or explain a failure. Keep the engineering decision with the person who can review the code and run the system. This section focuses on what makes an AI-assisted workflow useful and verifiable.

## Start here

- **[Follow the AI learning path](/docs/ai)** to connect AI-assisted work with software testing and computer science foundations.
- **[Read the AI-assisted development field note](/field-notes/ai-assisted-development)** for a workflow that starts with expected behavior and ends with a checked result.
- **[Try the service lab](/labs/build-and-operate-a-service)**, then ask an assistant to propose one small improvement and verify it yourself.

## Systems to study

- **[Agent Autoloop](/ai/agent-autoloop):** Study an event-driven loop that dispatches work to CLI agents, records progress, and asks for a human decision when needed. Based on the [upstream repository](https://github.com/KKKKhazix/agent-autoloop).

## Questions to carry into a project

- What part of the work can an assistant help with, and what evidence would show that it helped?
- Which assumptions, APIs, data boundaries, and failure cases need human review?
- Can another engineer reproduce the result without relying on the assistant's explanation?
