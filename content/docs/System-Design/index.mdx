# Systems Architecture

System design connects product requirements to technical boundaries and operating consequences. A strong design explains what must be true, which alternatives were considered, how the system fails, and how the organization will operate it over time.

## Design sequence

1. Clarify users, critical journeys, scale, latency, consistency, durability, security, compliance, and cost constraints.
2. Define APIs, data ownership, trust boundaries, and the simplest architecture that can meet the requirements.
3. Estimate traffic, storage, working set, fan-out, and growth to identify likely constraints.
4. Model failure domains, overload, partial failure, recovery, and safe change.
5. Choose data, messaging, caching, and compute components from their guarantees and operating model.
6. Define observability, SLOs, capacity, deployment, migration, and ownership.
7. Record tradeoffs, rejected alternatives, and conditions that should trigger redesign.
