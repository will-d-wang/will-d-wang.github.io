# Jenkins

Jenkins is an extensible automation server. Its flexibility makes controller security, plugin lifecycle, agent isolation, and shared-library governance central design concerns.

## Architecture and trust

Keep build execution on agents rather than the controller. Separate trusted release workloads from untrusted pull-request jobs, especially when agents have network access, persistent workspaces, or credentials. Prefer ephemeral agents and short-lived workload identity.

Store pipelines with source as a `Jenkinsfile`. Shared libraries can standardize delivery contracts, but version them, test changes against representative consumers, and publish migrations. Avoid allowing repository-controlled scripts to acquire controller or production authority before trusted review.

## Operate Jenkins

- minimize plugins and track their security and compatibility lifecycle;
- back up configuration, credentials metadata, job history needed for audit, and shared state;
- test controller restoration and agent bootstrap;
- restrict script approval, administrative access, and credential domains;
- monitor queue time, executors, controller health, agent failures, flaky jobs, and artifact publishing;
- upgrade through a staged environment with rollback and plugin compatibility checks.

Use Jenkins when its extensibility and existing investment justify the operating burden. Compare the full lifecycle and migration cost with managed CI services, not only pipeline syntax.
